# Artistic Album Naming and Missing-EXIF Review Design

## Goal

Improve AI-generated public album names so they read like intentional photography collections rather than literal visual labels. Re-running enrichment must preserve completed visual grouping, regenerate album metadata under the new naming policy, automatically resolve title/slug collisions, and produce a reviewable report for albums whose images have no EXIF capture date.

## Naming policy

Each public title must be concise, distinctive, pronounceable, and suitable for use as a collection name. The title describes the mood or identity of the set; literal details such as clothing, props, colors, and poses belong in SEO metadata and image alt text.

The AI chooses one coherent naming language for each album:

- Beauty, fashion, editorial, glamour, monochrome, cyber, and modern studio concepts may use polished English names such as `Midnight Frequency`, `Scarlet Trace`, or `Ivory Soirée`.
- Áo dài, Vietnamese wedding, family, heritage, and culturally traditional concepts should prefer poetic Vietnamese or Hán–Việt names such as `Xích Điệp`, `Mộng Lan`, `Nguyệt Hồng`, or `Dạ Triều`.
- Other portrait concepts may use either English or Vietnamese/Hán–Việt according to the visual direction, but one title must not mix the languages awkwardly.
- Hán–Việt vocabulary uses Vietnamese Latin spelling. The script must not emit Chinese characters.

Titles must avoid literal or repetitive templates such as `Nàng Thơ`, `Bộ Ảnh`, `Chàng Trai`, `Portrait`, `Beauty Portrait`, `Birthday Nàng Thơ`, or lists of visible objects. The AI must not copy a production title or another title already reserved in the same import.

Split parts retain the existing contract: one concept split over the 50-image limit is named `Tên Concept #1`, `Tên Concept #2`, and so on.

## Prompt versioning and refresh

Album enrichment receives an explicit prompt version. Existing album checkpoint entries created by an older prompt version are not reused for public metadata. When `enrich` is run after this change:

1. The seven completed visual-grouping windows remain reusable and are not sent to AI again.
2. Album title, slug, meta title, and meta description are regenerated under the new naming policy.
3. Existing category, tag, cover, and per-image alt decisions may be regenerated by the same album analysis so the metadata remains internally consistent.
4. Each successful result is saved to the existing enrichment checkpoint and manifest immediately, so interruption remains resumable.
5. Subsequent runs with the same prompt version reuse completed album results.

The progress output identifies refreshed or resumed album work without logging credentials or image data.

## Collision prevention and repair

Before album analysis, the importer reads the public production album catalog and builds a set of reserved normalized titles and slugs. During the import it also reserves each newly accepted title and slug.

An AI result is accepted only when its final part-aware slug is unique against:

- published production albums;
- albums already accepted in the current manifest run; and
- other parts after applying `#1`, `#2`, and subsequent suffixes.

If a result collides, the importer retries that album analysis with the conflicting and reserved titles supplied as exclusions. Collision repair is bounded to three naming attempts. An unresolved collision is recorded as an album enrichment failure; it is never silently accepted and cannot receive manifest approval.

Slug comparison uses the same `slugify` function as manifest generation, so accents, punctuation, and capitalization cannot hide a duplicate.

## Missing-EXIF report

Add a non-production report command that reads the manifest and writes a Markdown file. The report contains one section for every album with a missing `shootDate`, `missing_exif_date` review reason, or an image whose `capturedAt` is absent.

Each entry includes:

- current title and slug;
- number of images;
- current cover relative path;
- every source image relative path;
- an empty `Chosen shoot date` field for manual completion.

The default report path is `.artifacts/album-import/missing-exif-albums.md`. Generating the report does not alter the manifest, approval, checkpoint, source archive, AI service, or production.

The current manifest is expected to report 25 albums containing 166 missing-EXIF images. These albums remain blocked from approval until the operator supplies a valid shoot date and resolves the per-image missing-date review state, or explicitly removes the albums from the import manifest.

## Commands and operator flow

The operator first regenerates the missing-EXIF review file, then re-runs enrichment with the configured AI environment:

```powershell
npx -p node@24 node scripts/import-ndt-albums.mjs report-missing-exif `
  --manifest ".artifacts\album-import\manifest.json" `
  --output ".artifacts\album-import\missing-exif-albums.md"

npx -p node@24 node scripts/import-ndt-albums.mjs enrich `
  --manifest ".artifacts\album-import\manifest.json"
```

After reviewing names, resolving duplicate failures, and completing or excluding missing-date albums, the operator runs validation and approval. Production execution remains a separate explicit command and is outside this naming refresh.

## Error handling and safety

- A production album catalog read failure stops enrichment before new album AI work.
- Provider `429` and transient `5xx` responses retain the existing bounded retry and checkpoint behavior.
- A naming collision never falls back to a numeric slug unless it is a legitimate split part.
- Prompt-version refresh invalidates any previous manifest approval before mutation.
- No AI key, admin token, source image bytes, thumbnail data URL, or presigned URL is written to the manifest, checkpoint, report, or logs.
- The report command is read-only with respect to the manifest and production.

## Testing

Automated tests cover:

- artistic naming instructions, language selection, Hán–Việt spelling, banned templates, and production-title exclusions in the AI payload;
- old prompt-version checkpoint entries causing album metadata refresh while grouping checkpoints remain reusable;
- collision detection using normalized final slugs, AI retry with exclusion context, and hard failure after three conflicting results;
- distinct `#1` and `#2` split-part slugs;
- deterministic Markdown reporting of missing-date albums and image paths;
- no manifest mutation or network access from the report command;
- existing checkpoint, retry, concurrency, validation, production gate, and credential-safety tests.

Verification uses mocked AI and production reads only. It must not call real AI, upload files, approve the working manifest, or mutate production.
